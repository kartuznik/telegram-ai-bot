# Кузьма — умный Телеграм-бот ассистент

**Кузьма** — это многофункциональный ИИ-ассистент для Telegram на базе **OpenAI GPT-4o** (чат, голос Whisper, изображения Vision, файлы PDF/TXT) с живым стилем ответов, веб-поиском через **Tavily**, режимом **консьержа** (подбор актуальных вариантов из интернета), **редактором контента** для канала [@kriptogeograph](https://t.me/kriptogeograph) (черновики, авто-поиск, апрув в личке), **симулятором сценариев** («что если…» с тремя ветками), **шаблонами** и **якорями** в диалоге, статистикой и админ-командами.

> Скриншоты можно добавить сюда позже (`![Пример](docs/screenshot.png)`).

### Ключевые возможности

- Умный диалог с памятью контекста и адаптацией стиля под пользователя  
- Триггерный веб-поиск (Tavily) и кнопка **консьержа** для запросов вроде отелей, билетов, цен  
- Редактор контента: темы, web/TG/both, авто-поиск, черновики с кнопками ✅ ✏️ ❌  
- Создание черновиков по триггеру из PDF/TXT/MD, изображений и URL (через Tavily)  
- Новостной режим редактора: приоритет свежих новостей, anti-promo фильтры, антидубли и пометки качества; метрики фактчека и SEO — см. [docs/editorial-qualities.md](docs/editorial-qualities.md)  
- Обучение «голоса канала» по одобренным постам, рейтинг источников и подтверждение публикации просроченных черновиков  
- Симулятор сценариев: оптимистичный / реалистичный / пессимистичный разбор  
- Шаблоны (`/templates`) и якоря (`/bookmarks`)  
- `/selftest` для админа — проверка БД и ключевых подсистем  
- **Меню команд** в Telegram: для всех — пользовательский набор; для `ADMIN_ID` — дополнительно служебные (`setMyCommands` + `BotCommandScope`)  
- Поддержка голоса, фото, документов; SOCKS5-прокси для OpenAI и опционально для Telegram API

## Быстрый старт

**Нужно:** Python **3.10+**, `git`, доступ в интернет.

```bash
git clone <URL-репозитория> telegram-ai-bot
cd telegram-ai-bot
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
copy .env.example .env   # Windows; на Linux: cp .env.example .env
```

Отредактируйте `.env` — минимум:

```env
TELEGRAM_BOT_TOKEN=123456:ABC-DEF...   # от @BotFather
OPENAI_API_KEY=sk-...                    # от platform.openai.com
```

Запуск:

```bash
python main.py
```

Бот создаст SQLite-файлы `bot_database.db` и `bot_statistics.db` в корне проекта при первом старте. Напишите боту `/start` в Telegram.

## Подробная установка

### 1. Клонирование и виртуальное окружение

Рекомендуется изолировать зависимости в `venv`:

```bash
python -m venv .venv
source .venv/bin/activate   # или .venv\Scripts\activate на Windows
pip install --upgrade pip
pip install -r requirements.txt
```

Зависимости из `requirements.txt`: `aiogram`, `openai`, `pypdf`, `tavily-python`, `python-dotenv`, `aiohttp-socks`, `socksio` (транзитивно подтянутся и `httpx` и др.).

### 2. Файл `.env`

Скопируйте `.env.example` в `.env` и заполните секреты. **Не коммитьте** `.env` в git.

### 3. База данных

Инициализация выполняется **автоматически** при запуске `main.py`:

- `init_db()` — основная БД `bot_database.db` (пользователи, диалоги, настройки, шаблоны, якоря, черновики)  
- `init_stats_db()` — `bot_statistics.db` (статистика, активность по дням)  
- `init_admin_db()` — таблица банов в той же БД, что и статистика  

Ручная миграция не требуется для первого запуска.

### 4. Первый запуск

```bash
python main.py
```

В логах должны появиться строки о инициализации БД и запуске polling. Если указан `TAVILY_API_KEY`, в логах будет отметка о Tavily. Фоновая задача авто-поиска черновиков стартует вместе с ботом (интервал между **полными проходами** по пользователям — **15 минут**; частота **нового** черновика для одного пользователя задаётся в `/editor_prefs авто:ЧАСЫ`).

## Настройка и переменные окружения

| Переменная | Обязательно | Описание |
|------------|-------------|----------|
| `TELEGRAM_BOT_TOKEN` | **Да** | Токен бота от [@BotFather](https://t.me/BotFather). Формат: `число:строка`. |
| `OPENAI_API_KEY` | **Да** | Ключ API OpenAI ([платформа](https://platform.openai.com/)). Префикс обычно `sk-`. |
| `TAVILY_API_KEY` | Нет | Ключ [Tavily](https://tavily.com/) для веб-поиска и черновиков в режиме `web`/`both`. Без ключа диалог работает, но поиск и редактор в режиме только web — нет. |
| `ADMIN_ID` | Нет | Числовой Telegram user ID админа. Нужен для `/admin`, `/selftest`, `/broadcast`, банов. Узнать ID: [@userinfobot](https://t.me/userinfobot) или raw-данные апдейта. |
| `PROXY_HOST` | Нет | SOCKS5 для **OpenAI** (и клиента на httpx). Пример: `127.0.0.1` или хост VPS-прокси. |
| `PROXY_PORT` | Нет | Порт SOCKS5 для OpenAI, часто `1080`. |
| `PROXY_USERNAME` | Нет | Логин OpenAI-прокси, если требуется. |
| `PROXY_PASSWORD` | Нет | Пароль OpenAI-прокси. |
| `TELEGRAM_PROXY_HOST` | Нет | Отдельный SOCKS5 для **Telegram Bot API**. Если пусто — Telegram идёт напрямую (рекомендуется для VPS в Европе). |
| `TELEGRAM_PROXY_PORT` | Нет | Порт Telegram-прокси, часто `1080`. |
| `TELEGRAM_PROXY_USERNAME` | Нет | Логин Telegram-прокси, если требуется. |
| `TELEGRAM_PROXY_PASSWORD` | Нет | Пароль Telegram-прокси. |
| `TELEGRAM_PROXY_FALLBACK_DIRECT` | Нет | `1` / `true` — при сбоях Telegram через `TELEGRAM_PROXY_*` один раз переключить сессию на прямое подключение к api.telegram.org. |
| `LOG_LEVEL` | Нет | Уровень логирования: `DEBUG` / `INFO` / `WARNING` / `ERROR`. По умолчанию `INFO`. |
| `CONCIERGE_ENABLED` | Нет | `0` / `false` — отключить логику консьержа. По умолчанию включён. |
| `MODEL_TEMPERATURE` | Нет | Температура чата, диапазон в коде 0.5–0.9, по умолчанию `0.75`. |
| `VISION_MODEL_TEMPERATURE` | Нет | Температура vision, 0.15–0.55, по умолчанию `0.38`. |
| `MAX_USER_TEMPLATES` | Нет | Лимит шаблонов на пользователя (1–100), по умолчанию `30`. |
| `MAX_USER_ANCHORS` | Нет | Лимит якорей (1–100), по умолчанию `25`. |
| `TAVILY_TIMEOUT_SECONDS` | Нет | Базовый таймаут HTTP Tavily в секундах (10–120), по умолчанию `36`. |
| `TAVILY_MAX_RETRIES` | Нет | Число **дополнительных** попыток при таймауте (0–5), по умолчанию `2` (итого до 3 запросов). |
| `TAVILY_RETRY_BACKOFF_MULTIPLIER` | Нет | Множитель паузы между попытками (1.0–4.0), по умолчанию `2.0`. |
| `CONTENT_EDITOR_TG_DEFAULT_CHANNELS` | Нет | Список username публичных TG-каналов для парсинга `t.me/s/...` через запятую **без** `@`. Если пусто — используется встроенный набор в `app/config.py`. |
| `CONTENT_EDITOR_EXCLUDE_POSTED_DAYS` | Нет | Сколько дней учитывать **уже опубликованные** URL при исключении дублей (1–365), по умолчанию `14`. |
| `CONTENT_EDITOR_EXCLUDE_REJECTED_DAYS` | Нет | Сколько дней учитывать **отклонённые** URL при исключении (1–365), по умолчанию `7`. |
| `BLOCKED_SEARCH_DOMAINS` | Нет | Домены, которые редактор **не предлагает** в черновиках и передаёт в **Tavily** как `exclude_domains`: список через запятую (регистр не важен). Если переменная **не задана** — используется встроенный набор в `app/config.py` (tiktok, vm.tiktok, Steam/Epic/App Store/Google Play и т.д.). Если задана **пустая строка** — дополнительная блокировка по этому списку отключена (остаются только промо-домены `WEB_PROMO_DOMAINS` в исключениях Tavily). |

Что можно не трогать: все переменные кроме `TELEGRAM_BOT_TOKEN` и `OPENAI_API_KEY` имеют разумные дефолты или опциональны.

Модель чата в коде по умолчанию **`gpt-4o`** (поле `Config.model_name`; при необходимости расширьте `load_config()` под переменную окружения).

## Команды бота

Команды в чате доступны по тексту; **меню слева от поля ввода** подстраивается под роль (см. [Меню команд Telegram](#меню-команд-telegram)). Справка **`/help`**: обычному пользователю показывается только «свой» список; админу дополнительно блок служебных команд.

### Общие (все авторизованные пользователи)

| Команда | Описание |
|---------|----------|
| `/start` | Приветствие, кнопка «Что я умею?» → справка. |
| `/help` | Возможности бота и команды **с учётом роли** (у админа — пометка админ-блока). |
| `/simulate` | Симулятор сценариев; вопрос можно дописать в той же строке после команды. |
| `/clear` | Очистить историю диалога в памяти/БД для этого чата. |
| `/reset_style` | Сбросить настройки стиля ответов (`user_preferences`). |
| `/templates` | Список шаблонов ответов. |
| `/bookmarks` | Список якорей в диалоге. |

**Примеры без слэша:** «сохрани это», «запомни этот момент», «покажи шаблоны» — эвристики в `user_templates`, `user_anchors`.

### Редактор контента (только **личка** с ботом)

| Команда | Описание |
|---------|----------|
| `/editor_start` | Включить редактор и авто-поиск (по настройке). |
| `/editor_stop` | Выключить редактор и авто-поиск. |
| `/editor_prefs` | Настройки: подробности в подразделе **«Редактор контента»** ниже. Поддерживаются отдельные директивы **`темы:`** / **`тгканалы:`** (или без двоеточия: `темы …`, `тгканалы …`), **`источники:`**, **`авто:`**, **`дедлайн:`**; их можно **комбинировать в одной строке**, например: `/editor_prefs источники:tg тгканалы:@a,@b темы:мемы,юмор авто:0.5 дедлайн:24`. |
| `/editor_info` | Текущие настройки редактора: темы, каналы, режим источников, авто, дедлайн, статус «голоса канала», топ/анти-топ источников. |
| `/editor_reset_rejects` | Сбросить список отклонённых URL и связанные «баны» по конкретному сайту или **`tg:username`** (не весь домен `t.me`). |
| `/drafts` | Показать **самый старый** неапрувнутый черновик из очереди или создать новый, если очередь пуста. |
| `/drafts ещё` | То же, что «добавить ещё один черновик в хвост очереди»: сработают также `еще`, `new`, `more`, `+`. Не более **6** черновиков в статусе `draft` одновременно. |

### Админ (`user_id == ADMIN_ID`)

| Команда | Описание |
|---------|----------|
| `/stats` | Статистика бота (для остальных пользователей команда заблокирована middleware). |
| `/admin` | Краткая сводка админки. |
| `/selftest` | Самодиагностика функций (только админ). |
| `/fulldiag` | Полная диагностика: техника + функционал (только админ). |
| `/status` | Техническое состояние процесса/БД (админ или владелец). |
| `/restart` | Перезапуск процесса через `exec` (только владелец `504425191`). |
| `/broadcast` | Рассылка (см. `main.py` / `admin.py`). |
| `/ban`, `/unban`, `/users` | Баны и список пользователей из статистики. |

## Меню команд Telegram

При старте бота (`main.py`, после `get_me()`) вызывается `setup_bot_command_menu` из `app/telegram_ui.py`:

- **`BotCommandScopeDefault`** — список **пользовательских** команд для всех (без `/stats`, `/admin`, …).
- **`BotCommandScopeChat(chat_id=ADMIN_ID)`** — **полный** список для админа в его личке с ботом.
- Для владельца `OWNER_RESTART_USER_ID=504425191` отдельно выставляется меню со служебными `/status` и `/restart` (даже если он не совпадает с `ADMIN_ID`).

Так меню у иконки «☰» и подсказки после `/` автоматически различаются; проверка прав на каждое сообщение для отрисовки меню не нужна. Если **`ADMIN_ID` не задан**, в логах будет предупреждение, расширенное меню для админа не установится.

**Важно:** админ хотя бы раз должен **написать боту в ЛС**, иначе `setMyCommands` для `BotCommandScopeChat` может завершиться ошибкой (чат с ботом ещё не создавался).

## Основные функции

### 1. Умный диалог и стиль Кузьма

Системный промпт в `app/llm_agent.py` задаёт тон: по-русски, с юмором, метафорами, эмодзи, кнопки JSON в конце ответа. Блок **стиля пользователя** подмешивается из `app/user_style.py` на основе `user_preferences`.

**Голос:** сообщения с голосом транскрибируются Whisper, дальше как текст.  
**Фото:** Vision (модель `gpt-4o` в коде анализа изображений).  
**Файлы:** PDF и TXT — извлечение текста (`app/pdf_extractor.py`), дальше в контекст модели.

### 2. Консьерж

При распознанном «намерении действия» и ответе модели с кнопкой `concierge_run` пользователь может запустить поиск Tavily по сохранённому запросу. Реализация: `LLMAgent.search_with_tavily`, callback в `main.py`. Без `TAVILY_API_KEY` поиск недоступен — бот честно сообщит об этом.

### 3. Редактор контента (@kriptogeograph)

- Включение: `/editor_start` в **личке**. Без лички команды редактора не отрабатывают.  
- **Темы и каналы раздельно:** можно менять только темы или только TG-каналы одной командой — через явные директивы **`темы:`** / **`темы `** (пробел после слова) и **`тгканалы:`** / **`тгканалы `**; также поддерживаются **`источники:`**, **`авто:`**. В одной строке:  
  `/editor_prefs источники:tg тгканалы:@a,@b темы:мемы,юмор авто:0.5`  
- **Несколько тем в `темы:`:** список через запятую целиком сохраняется как темы, например:  
  `/editor_prefs темы:юмор,игры,аниме,twitch`  
- **Классическая строка без «темы:»:** `/editor_prefs биткоин,defi` — по-прежнему первая часть до запятой → темы, вторая → уточнение к поиску.  
- **Источники:** `источники:web` — Tavily; `tg` — публичные ленты `https://t.me/s/username` (см. `tg_feed_fetcher.py`); `both` — оба (без ключа Tavily веб может быть недоступен).  
- **Свежесть веб-новостей:** при web-поиске редактор сначала запрашивает материалы примерно за последние 2 дня; если пусто — делает fallback на окно до 5 дней.  
- **Антипромо-домены в веб-поиске:** рекламные/витринные домены отфильтровываются на этапе запроса, чтобы в черновики реже попадал «маркетинговый» контент.  
- **TG-каналы:** список через запятую или пробел: `@a,@b` или `@a @b`. Дефолтный набор — `CONTENT_EDITOR_TG_DEFAULT_CHANNELS` или встроенный список в `config.py`. При каждом поиске каналы **перемешиваются** (shuffle в логах) для разнообразия выдачи.  
- **Новостной стиль черновика:** редактор переписывает рекламно звучащие фрагменты в фактологичный новостной тон (без рекламных призывов).  
- **`/editor_info`** — человекочитаемая сводка prefs: источники, дедлайн, состояние «голоса канала» и качество источников.  
- **`/editor_reset_rejects`** — сброс отклонений: для веба банится хост, для Telegram — ключ вида **`tg:username`**, а не весь домен `t.me`.  
- **Дубликаты URL:** уже опубликованные и недавно отклонённые ссылки не предлагаются снова; окна задаются **`CONTENT_EDITOR_EXCLUDE_POSTED_DAYS`** (по умолчанию 14) и **`CONTENT_EDITOR_EXCLUDE_REJECTED_DAYS`** (по умолчанию 7).  
- **Семантический антидубль:** похожие по смыслу заголовки из недавних одобренных постов отбрасываются, чтобы не гонять одну и ту же новость разными словами.  
- **Очередь черновиков:** одновременно не более **6** записей в статусе «черновик» (`draft`). Команда **`/drafts`** показывает самый старый на решение; **`/drafts ещё`** (и синонимы `еще`, `new`, `more`, `+`) добавляет ещё одну подборку в хвост, если лимит не исчерпан.  
- **Дедлайн черновика:** `/editor_prefs дедлайн:24|48|72`; просроченные автоматически получают статус `expired` и не идут в обычную выдачу `/drafts`.  
- **Подтверждение просроченного апрува:** если черновик устарел, перед публикацией бот спрашивает «Да, публикуем / Нет, отменить».  
- **Авто:** `авто:ЧАСЫ` — пауза между **попытками** авто-черновика для пользователя; `авто:off` — только ручной `/drafts`. Глобальный обход пользователей в фоне — каждые **15 минут** (`content_editor_background.py`).  
- **Апрув:** кнопки ✅ в канал, ✏️ правка, ❌ отказ; после ✅ бот сразу показывает следующий черновик из очереди, а если очередь пуста — присылает короткое уведомление (с учётом авто-режима). Отказ влияет на исключения URL и учёт «банов» канала/хоста (подробности в `content_editor.py`).
- **Обучение голоса канала:** после серии одобренных публикаций редактор начинает подмешивать примеры «удачного» стиля в генерацию новых черновиков.  
- **Рейтинг источников:** каналы, которые чаще получают ✅, поднимаются в приоритете; каналы с частыми ❌ опускаются. В `/editor_info` показываются топ-5 и худшие 3.
- **Срочные новости:** материалы с маркерами breaking/srочно получают повышенный приоритет.
- **Контроль качества черновика:** если текст выглядит слабым по фактуре, в конце добавляется пометка «черновик требует проверки».
- **Верификация источника и исторический контекст:** для web-материалов добавляется пометка «источник проверен/не верифицирован», а при совпадении темы может добавляться ссылка на ранее одобренный похожий пост.
- **Черновики из файлов/изображений:** если в подписи к документу/фото есть триггер (`черновик`, `в канал`, `draft` и т.п.) или триггер был в недавнем сообщении, бот соберёт черновик из `PDF/TXT/MD` или описания изображения.
- **Черновики из URL:** если в тексте есть триггер и ссылка `https://...`, бот заберёт статью через Tavily и соберёт черновик с источником.

**Примеры (копировать в Telegram):**

```text
# Только темы
/editor_prefs темы мемы,юмор,новости

# Только каналы
/editor_prefs тгканалы @bezposhady,@toporlive,@cybers

# Всё вместе
/editor_prefs источники:tg тгканалы:@a,@b темы:мемы,юмор авто:0.5 дедлайн:24

# Проверить настройки
/editor_info

# Черновик или очередь
/drafts

# Ещё один материал в очередь (до 6 неапрувнутых)
/drafts ещё

# Сбросить баны/отказы по источникам
/editor_reset_rejects

# Изменить дедлайн жизни черновика
/editor_prefs дедлайн:48
```

### 4. Симулятор сценариев

Запросы вида «что если…», «какие варианты…» классифицируются в `scenario_simulator.py`, генерируются три сценария (🟢🟡🔴), кнопки для углубления. Данные сессий — в памяти процесса (`put_session` / `get_session`).

### 5. Шаблоны и якоря

- **Шаблоны** — сохранённые **готовые тексты** ответов ассистента для повторного использования (`user_templates`, таблица `user_templates`).  
- **Якоря** — закладки на **фрагмент переписки** (контекст), не то же самое что шаблон (`conversation_anchors`).

### 6. Самодиагностика `/selftest`

Класс `BotSelfTest` в `app/selftest.py` проверяет наличие таблиц, шаблоны/якоря, ключи (в т.ч. Tavily), и возвращает текстовый отчёт админу. Используйте после деплоя или смены `.env`.

## Деплой на VPS (systemd)

### Подготовка (Ubuntu/Debian)

```bash
sudo apt update && sudo apt install -y python3 python3-venv python3-pip git
sudo useradd -r -m -s /bin/bash tgbot   # опционально отдельный пользователь
sudo mkdir -p /opt/telegram-ai-bot
sudo chown tgbot:tgbot /opt/telegram-ai-bot
```

Скопируйте проект, создайте venv, установите зависимости, положите `.env` с секретами.

**Перед продакшеном проверьте:**

- **`ADMIN_ID`** — числовой Telegram user ID: без него нет разделения меню команд для админа и не работают админ-хендлеры как «свои».  
- **Редактор:** при необходимости задайте `CONTENT_EDITOR_EXCLUDE_*`, `CONTENT_EDITOR_TG_DEFAULT_CHANNELS`, таймауты Tavily — чтобы не упираться в лимиты и дубликаты.  
- **Бэкап SQLite** — в `bot_database.db` лежат настройки, черновики, шаблоны, якоря; в `bot_statistics.db` — активность и баны. Регулярно копируйте оба файла (см. ниже).

### Unit-файл systemd

`/etc/systemd/system/kuzma-bot.service`:

```ini
[Unit]
Description=Kuzma Telegram AI Bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=tgbot
Group=tgbot
WorkingDirectory=/opt/telegram-ai-bot
Environment=PYTHONUNBUFFERED=1
ExecStart=/opt/telegram-ai-bot/.venv/bin/python /opt/telegram-ai-bot/main.py
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now kuzma-bot.service
sudo journalctl -u kuzma-bot.service -f
```

Перезапуск: `sudo systemctl restart kuzma-bot.service`.

### Бэкап SQLite

Рекомендуется планировать копирование **обоих** файлов — там и пользовательский контент редактора, и статистика с банами.

```bash
# остановить бота на время бэкапа — согласованно с окном обслуживания
sudo systemctl stop kuzma-bot.service
cp /opt/telegram-ai-bot/bot_database.db /backup/bot_database_$(date +%F).db
cp /opt/telegram-ai-bot/bot_statistics.db /backup/bot_statistics_$(date +%F).db
sudo systemctl start kuzma-bot.service
```

## Мониторинг и диагностика

- **Команды:**
  - `/status` — технический отчёт (метрики + доступность БД), доступ: админ или владелец.
  - `/selftest` — функциональная самопроверка подсистем, доступ: только админ.
  - `/fulldiag` — объединённая диагностика (техника + функционал), доступ: только админ.
  - `/restart` — безопасный перезапуск процесса через `exec`, доступ: только владелец `OWNER_RESTART_USER_ID=504425191`.
- **Auto-diagnostics loop:** запускается в фоне в `main.py` с интервалом `1800` секунд (30 минут).
- **Heartbeat middleware:** `install_diagnostics_heartbeat_middleware()` отмечает входящую активность на апдейтах (`message`, `edited_message`, `callback_query` и др.), чтобы отличать «тихий период» от реального зависания.
- **Сценарии авто-восстановления:**
  - если основная БД перестала отвечать — отправляется алерт и выполняется рестарт процесса;
  - если `bot.get_me()` падает `3` раза подряд — отправляется алерт и выполняется рестарт процесса;
  - если polling не получает апдейты ~90+ минут, выполняется принудительный перезапуск polling.

## Устранение проблем

| Симптом | Что проверить |
|---------|----------------|
| `ModuleNotFoundError` | Активирован ли venv, выполнен ли `pip install -r requirements.txt`. |
| `TELEGRAM_BOT_TOKEN is missing` | Файл `.env` в **корне** проекта (рядом с `main.py`), переменная без кавычек или в кавычках по правилам dotenv. |
| `TelegramConflictError` / «другая копия» | Запущено два процесса с одним токеном — остановите дубликат. |
| Tavily timeout / пустой поиск | Увеличьте `TAVILY_TIMEOUT_SECONDS`, `TAVILY_MAX_RETRIES` в `.env`; смотрите логи `Tavily search:`. |
| OpenAI `403 Forbidden` (`unsupported_country_region_territory`) | Проверьте маршрут к OpenAI: для OpenAI используйте `PROXY_*`, для Telegram — отдельно `TELEGRAM_PROXY_*` или direct. Убедитесь, что прокси отвечает и страна выхода поддерживается OpenAI. |
| Бот молчит | `journalctl` или консоль; проверьте бан в `banned_users`; проверьте сеть и прокси. |
| Авто-поиск не шлёт черновики | В ЛС `/editor_prefs` — авто включён? не пауза? не лимит черновиков? режим `источники:web` без Tavily — для пользователя тик пропускается. |
| Редактор «нет Tavily» | Добавьте ключ или `источники:tg` / `both`. |
| «Все» TG-каналы перестали давать новости | Возможно в «отказах» забанен конкретный канал (`tg:username`). Выполните **`/editor_reset_rejects`** и проверьте **`/editor_info`**. |
| Снова и снова одна и та же новость | Убедитесь, что материал **опубликован** (✅), а не висит в очереди как `draft`; иначе URL может не попасть в ветку «posted» для исключений. |
| Черновики не копятся в очереди | Используйте **`/drafts ещё`** (или `more`, `+` и т.д.), пока не достигнут лимит **6** неапрувнутых. |
| Будто игнорирует `тгканалы:` | Синтаксис: **`тгканалы:`** или **`тгканалы `** затем `@a,@b` или `@a @b`; опечатка **`тканалы`** не сработает. |
| Бот пишет только первую тему из списка | Обновите бота — баг парсинга `темы:` исправлен. |
| Лишний дисклеймер «не является инвестиционной рекомендацией» | Фикс апреля 2026: классификация финансовости идёт по контенту (`title`/`snippet`), а не по пользовательским `topics`. Обновите до актуальной версии, если видите старое поведение. |
| Почему черновик «пропал» из очереди | Проверьте дедлайн: просроченные переходят в `expired` и не выдаются как обычные `draft`. |
| Бот просит отдельное подтверждение перед публикацией | Это защита для просроченного материала: подтвердите кнопкой «Да, публикуем» или отмените. |
| Источники «ведут себя странно» (часть каналов почти не попадает) | Проверьте `/editor_info`: работает рейтинг качества источников, частые ❌ снижают приоритет канала. |
| В конце появился текст «черновик требует проверки» | Это автоматическая метка слабой фактуры/структуры; проверьте и вручную доработайте перед ✅. |
| Новость не приходит повторно, хотя формулировка другая | Включён семантический антидубль по заголовкам недавних одобренных постов. |
| «Источник не верифицирован» внизу черновика | Для web-материала домен не входит в список доверенных источников; проверьте первоисточник вручную. |
| В логах shuffle, а каналы «те же» | Shuffle меняет порядок обхода; список каналов смотрите в **`/editor_info`** — возможно в prefs сохранено мало каналов. |
| У админа в меню нет `/stats` | Задан ли **`ADMIN_ID`**; писал ли админ боту в ЛС; перезапустите бота и смотрите логи `setup_bot_command_menu`. |

**Сброс стиля пользователя:** `/reset_style`. Полный сброс prefs — вручную через SQL в `user_preferences` (осторожно).

**Логи:** уровень задаётся переменной окружения `LOG_LEVEL` (`DEBUG` / `INFO` / `WARNING` / `ERROR`), по умолчанию `INFO`.

## Развитие проекта

### Новая команда

1. Добавьте хендлер в `main.py`:  

```python
@router.message(Command("mycommand"))
async def mycommand_handler(message: Message) -> None:
    await message.answer("OK")
```

2. Добавьте строку в **`build_user_bot_commands()`** (и при необходимости в **`build_admin_bot_commands()`**) в `app/telegram_ui.py`, чтобы команда появилась в меню после перезапуска (`setMyCommands`).  
3. Расширьте текст справки в **`build_help_text`** / константах `_HELP_*` в том же файле.

### Изменить стиль ответов

Основной системный промпт — константа `SYSTEM_PROMPT` в `app/llm_agent.py`. Кнопки и JSON — там же. Редактор постов — `DRAFT_SYSTEM` в `app/content_editor.py`.
